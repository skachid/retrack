# Notes for Claude Code

## What this is
A tool that checks indie music catalogs against The MLC's Public Search API and flags royalty gaps (red/yellow/green). The customers are small indie labels, managers and producers. They distrust generative AI, so the product never touches audio, never trains on their data, and doesn't market itself as "AI".

## The owner
A junior developer learning as he goes. When you make changes:
- Explain *why* in plain words, briefly, and name the concept (e.g. "this is dependency injection").
- Prefer simple, readable code over clever code.
- Keep the tests passing (`pytest`) and add a test for every new rule.

## Code map
- Docs: `README.md` is the public front door (what Retrack is, who it's for, the web flow, privacy, `COMPLIANCE_TEXT`, status; under ~80 lines, no setup). Setup lives in `docs/SETUP.md` (install, `.env` table, Stripe test and restricted keys, webhook testing with `stripe listen --events checkout.session.completed,checkout.session.async_payment_succeeded --forward-to localhost:8000/stripe/webhook`, MLC API access, hosting), the command line in `docs/CLI.md` (`import`, `--ai-search`, `--fix`, the HTML report, CSV format), and the web flow, AI costs, architecture, known limits and roadmap in `docs/HOW_IT_WORKS.md`. Error messages and startup tips that point at docs name `docs/SETUP.md`.
- `retrack/mlc_client.py`: API client (`MLCClient`) + `MockClient`. Both have `search_recordings(isrc)`, `get_works(song_codes)` and `search_songcode(title, writers)` (writers = plain names; `search_writers()` turns them into SearchWriter objects).
- `retrack/checker.py`: verdict rules. All red/yellow/green logic lives here, including the RED split (`red_case`: `NOT_LINKED` / `NOT_FOUND`) and the `WORK_MATCH_MIN_CONFIDENCE` bar.
- `retrack/work_search.py`: `--ai-search`. `search_for_work()` runs the exact search + variants (max `MAX_SEARCHES`=5 per song, max `MAX_CANDIDATES`=5 judged). `ClaudeWorkSearcher` + `MockWorkSearcher` (with `--mock`), both with `suggest_queries()` and `judge()`. It only suggests; never decide a verdict there. Sends only titles + writer names. Suggestions are always shown as "please confirm".
- `retrack/importer.py`: `python -m retrack import file.{csv,xlsx} --out catalog.csv [--smart-import] [--mock] [--yes]`. Reads any spreadsheet (busiest sheet, merged cells filled, header row found in the first 30 rows), maps columns, shows the mapping for the user to confirm or edit, then converts with plain Python. Offline `HeaderRuleMapper` is the default (also the fallback when the AI fails); `ClaudeColumnMapper` runs only with `--smart-import` (and not with `--mock`). Both have `map_columns(headers, samples)`. When the rule mapper has a missing or low-confidence field (`unclear_fields`), the output suggests `--smart-import` (`smart_import_hint`). Cleanup rules (`clean_isrc`, `split_writers`, duplicates, missing ISRC/writers) and their problems go to `import_problems.csv` with spreadsheet row numbers.
- `retrack/fixes.py`: the fix pack. Web UI only: `sold_kind()` (a red song not placed yet is `UNRESOLVED`, sold at the same price) and `plan_fixes(..., sell_red=True)` (fills `plan.unresolved` = "Check by hand", and `plan.all_set` for paid songs a closer look found fine); the CLI keeps `sell_red=False`. The rest: (`--fix` / `--fix-songs`, `--template`, `--i-confirm`), written to `fix_pack/`. `plan_fixes()` → `build_fix_pack()`. REGISTER (Not found anywhere) → a filled copy of the user's MLC template (or `registration_worksheet.csv`), LINK (not linked) → `match_suggestions.csv` (for review) + `BulkMatchSuggestions_YYYYMMDD.csv` (The MLC's exact format), CLAIM (yellow) → `claim_checklist.md`, plus `ATTESTATION.txt` and `README.md`. Template columns are found by header name (`classify_header`), never by hard-coded letters.
- `retrack/compliance.py`: `COMPLIANCE_TEXT`, `NEVER_TEXT`, `ATTESTATION_TEXT`. Import them; never reword them elsewhere.
- `retrack/ai.py`: the AI's model and money. `MODEL` (`claude-haiku-4-5`) is the one model every Claude call uses; `PRICES_PER_MTOK` and `cost_usd()` estimate cost from token counts. Web UI only: `MeteredClient` wraps the Anthropic client, checks the session's `OrderBudget` (MAX_SEARCHES calls per paid song, added in `mark_paid`) and the shared `DailySpend` (`RETRACK_AI_DAILY_LIMIT_USD`, default $5, in memory, per UTC day) before each call, raises `AILimitReached` (handled like "no answer"), and adds up tokens and dollars. The Claude classes call `client.messages.create` with structured output only (Haiku 4.5 takes no `effort` and has no server-side fallback).
- `retrack/name_matcher.py`: second-pass writer-name check. `ClaudeNameMatcher` (Claude API, opt-in via `--smart-names`) + `MockNameMatcher` (offline, used with `--mock`). Both have `same_person(a, b)`.
- `retrack/report.py`: output (terminal, CSV, `render_html`), and `findings_summary()` (the web UI's Summary: counts red cases and the finding codes `checker.py` records on each Result, so no rule is repeated). HTML is one self-contained file: CSS from `retrack/report.css` inlined, no JS, no web fonts/CDNs. Escape all catalog text with `html.escape`.
- `retrack/report.css`: report styles (Hallmark, theme Specimen). Every colour/font is a token in `:root`.
- `retrack/web.py`: the web UI's routes (`python -m retrack.web [--mock | --mock-mlc]`; `--mock-mlc` = sample MLC data and offline AI like `--mock`, but payments from the environment, so real Stripe test checkout when test keys are set): upload → columns (mapping only) → free check (no separate Check step: `POST /columns` starts it, with "Start the free check" and `CHECK_LINE` on the Columns page; the scan runs in a background thread, `run_scan` over `session.todo`, which never calls the AI; `POST /scan` only reruns it after an MLC error, and `GET /check` redirects for old links) → results (unplaced red songs are sold as `UNRESOLVED`: "Needs fixing: we’ll work out exactly how after checkout.") → tick songs → pay (`/pay`: the two extra checks via `extra_checks()`, saved in `session.settings` and run only after checkout, then the attestation; a missing AI key is reported here, before any payment) → Stripe Checkout → `/paid` (verified with Stripe) → `/fixes` (the first visit after paying runs `_finish_paid_songs`: `run_scan` again in the "finish" phase, only on paid songs that `checker.needs_ai_after_checkout()` picks, AI search only for red ones, with "Working out how to fix song N of M…", then logs the order's AI usage) (on-screen fix pack, laid out like the results: Register/Link/Claim count row, tabs, one closed row per song; in each group the songs come first, then short bold-verb steps with one "More detail" disclosure (`STEPS_FOR` holds verb, short line and full text), then its file for The MLC; kinds with no songs get no tile, tab or section) with downloads `fixes.xlsx`, `bulk_match.csv` and, after `POST /template`, `bulk_work_registration.xlsx`. Plus `recheck` (after checkout: AI search for the paid red songs it was off for, only those), delete and `/privacy`. `order_is_paid()` is the only test for "paid" and `mark_paid()` the only way to unlock (both module-level, idempotent), used by the return page `/paid`, `_sync_order()` (re-checks an open order on the results/fixes pages) and `POST /stripe/webhook` (signed; the one POST exempt from the Origin check). `/s/<id>/time_left` feeds the fix page's live countdown. No rules here: it only calls `importer`, `checker`, `fixes` and `privacy`. The scan writes `catalog.csv` and reads it with `load_catalog`, the same path as the CLI. `Config` injects the MLC client, `make_claude` (the raw Anthropic client), the matcher/searcher factories (each takes the metered client; `None` with `--mock`) and `daily`. Binds 127.0.0.1, checks the Origin header on every POST, caps 5 MB uploads / 500 songs.
- `retrack/web_pages.py`: the HTML of each step (`home_page`, `columns_page`, `progress_page`, `results_page`, `pay_page`, `fixes_page`, `privacy_page`, `error_page`) and the shared `layout` (sample-data banner, step list, footer with the compliance text). Shares `summary_html`/`groups_html` with the report.
- `retrack/sessions.py`: `SessionStore`, one private folder (0700) per upload under the temp dir's `retrack-sessions/`. Each session lives `SESSION_SECONDS` (60 minutes) from upload, payment included: `sweep()` deletes older ones (on every request and from a timer) and `expired()` lets the page say why. Clears leftovers on start, `delete()` for "Delete my files now", `delete_all()` when the server stops. Holds `attestation`, the open `order` and `paid_songs`.
- `retrack/payments.py`: `payments_from_env()` picks the mode: `DemoPayments` (`--mock` or no `STRIPE_SECRET_KEY`: "Pay (demo)", no Stripe) or `StripePayments` (hosted Checkout via `stripe.StripeClient(...).v1.checkout.sessions`). Raises `PaymentConfigError` for a live key without `RETRACK_PAYMENTS_LIVE=1`. `verify_webhook()` checks Stripe's signature with `STRIPE_WEBHOOK_SECRET` via `stripe.Webhook.construct_event` (raw body, timestamp tolerance); `WEBHOOK_EVENTS` are `checkout.session.completed` and `checkout.session.async_payment_succeeded`.
- `retrack/env.py`: `load_env()` reads `.env` (or `RETRACK_ENV_FILE`) at startup without overriding variables already set. `tests/conftest.py` points it at a missing file so tests never read a real `.env`.
- `retrack/privacy.py`: `data_flows(smart_names, ai_search, mock)`, the single source of truth for what leaves the computer (`mlc`/`claude` for the free check, where `claude` is always empty; `mlc_paid`/`claude_paid` for after checkout, paid songs only), and `privacy_items()`, the copy built from it.
- `retrack/home.css` + `home.js`: web UI design (Hallmark, Specimen, extends report.css). Every page must work with JS off; the script only picks text the server already made (progress, price lines, privacy variants).
- `retrack/preview.py`: `--serve`. Binds 127.0.0.1:8000 only and serves the report only (never the folder: `.env` lives there).
- `fixtures/import/`: made-up files shaped like a DistroKid export (CSV), a TuneCore export and a messy label sheet (.xlsx). Rebuild the .xlsx files with `python fixtures/import/build_import_fixtures.py`.
- `fixtures/mlc_mock.json`: fake API responses shaped like the real spec. `songcode_search` holds what `/search/songcode` can find: "THE BLUE HOUR" (BH3456, unlinked match for Blue Hour), a "BLUE HOUR" look-alike by another writer (must not match), and CG9013 (second registration of Concrete Garden).

## MLC API facts (spec v1.2.0, public-api.themlc.com/api/doc)
- Auth: `POST /oauth/token` with username/password → `accessToken` (Bearer).
- The only ISRC lookup is `POST /search/recordings` → gives `mlcsongCode`.
- `POST /works` takes `[{"mlcsongCode": ...}]` (lowercase s) → writers, publishers, `collectionShare`.
- `POST /search/songcode` takes `{"title", "writers": [{"writerFirstName", "writerLastName", "writerIPI"}]}` (no field required) → array of `{"mlcSongCode"` (capital S), `"workTitle", "iswc", "writers": [{writerId, writerFirstName, writerLastName, writerIPI, writerRoleCode}]}`. How it matches (exact/fuzzy) isn't documented.
- There is no ISRC→work or ISWC lookup.

## MLC process facts (from The MLC's help pages, checked Nov 2026)
- Bulk Work Registration: Portal → Works Registration → Bulk Registration Tool. `.xlsx`, columns must not move, max 300 rows, a work title appears once per document, each extra writer on its own row below with the work columns blank. Publishing info only for shares you control. Collection share can't be 0.
- Bulk Match Submission: CSV UTF-8, header exactly `ISRC,MLC Song Code`, no blank rows, no duplicate ISRCs, named `MemberName_BulkMatchSuggestions_YYYYMMDD.csv`, emailed to bulk.matching@themlc.com, 30–90 days.

## Compliance rules
These keep Retrack honest and safe to sell. Every change must keep them, and `tests/test_fixes.py` checks them.
- **No files without attestation.** Before a fix pack is written, the user confirms `ATTESTATION_TEXT` (they reviewed the data and control the shares), by typing yes at the prompt or with `--i-confirm`. `build_fix_pack()` refuses without an `Attestation` and writes nothing. The confirmation, how it was given and a UTC timestamp go in `ATTESTATION.txt`. Without a terminal and without `--i-confirm`, there's no confirmation.
- **Never guess ownership.** Publisher shares, IPIs, role codes and publisher names are never filled in, inferred or suggested, not even by the AI. Only facts from the catalog and The MLC are pre-filled; ownership cells stay blank, highlighted and marked `YOU MUST FILL THIS IN`.
- **Never recreate The MLC's template.** The user downloads it from their own MLC Portal and passes `--template`. Fill a copy (openpyxl); never change the original. Without a template, write the CSV worksheet that is clearly labelled as not the template, and say how to get the template. (Tests may build a fake template; product code never does.)
- **No duplicates.** Include the MLC song code whenever a work already exists. If the template has no song code column, such songs go in the claim checklist, not the template. Red songs without `--ai-search` are skipped, not registered.
- **One flat price.** `FIX_PRICE_USD` per fixed song, the same for every verdict. No per-verdict pricing. The summary shows "N songs × $X = $Total" (`price_line`).
- **Compliance text.** `COMPLIANCE_TEXT` on the HTML report, the homepage, every web page (footer), the pay and fix pages, the CLI fix pack's `README.md`, `ATTESTATION.txt` and `claim_checklist.md`, and the Summary and Confirmation tabs of `Retrack_Fixes_YYYYMMDD.xlsx`. It never goes inside a CSV or a file whose format The MLC dictates: the template copy and the bulk match CSV stay exactly in The MLC's format, and the CLI's `match_suggestions.csv` and `registration_worksheet.csv` start with their header row, with no `#` note lines (what they are is explained in the README).
- **Spreadsheets Retrack makes have headers on row 1.** Every data tab of `Retrack_Fixes_YYYYMMDD.xlsx` (Summary, Register, Link, Claim, Confirmation) starts with its headers on row 1, with no note rows above them. Ownership cells there are blank, highlighted and commented "YOU MUST FILL THIS IN", as in the template copy.
- **MLC-format files stay exactly in The MLC's format.** The template copy is untouched apart from the filled rows (cell values, plus yellow highlights and "you must fill this in" comments on those rows): no extra tabs, no notes, no changed properties, columns never moved. The bulk match CSV is exactly `ISRC,MLC Song Code`, UTF-8, no blank rows, no duplicate ISRCs.
- **No MLC branding.** No MLC logos or images anywhere. Say "The MLC" in plain text only, and never imply endorsement.
- **Hands off the Portal.** Retrack never logs into a customer's MLC Portal, never asks for a customer's Portal login or password, and never uploads or submits anything on the user's behalf. Fix pack code makes no network calls. Retrack's own Public Search API credentials in `.env` are fine (that's our API access, not a customer's Portal login); they're never prompted for and never written to any output.
- **Web UI: files stay on this machine and are deleted.** Uploads live only in `SessionStore` folders: deleted on "Delete my files now", when the server stops, and (leftovers from a crash) when it starts. Never write uploads anywhere else.
- **Web UI: privacy copy matches what happens.** Every "what leaves this computer" sentence comes from `privacy.privacy_items()`, built on `data_flows()`. If a check starts sending something new, update `data_flows()`; `tests/test_web.py` runs real visits (free check, then checkout) for all four toggle settings and fails if what's sent at either stage differs from what's declared.
- **AI costs money, so it's tied to paid songs.** In the web UI the free check never calls the AI, whatever the toggles say. After checkout, AI search runs only on paid red songs and smart names only on paid songs with a missing writer. Every call goes through `ai.MeteredClient`: at most `MAX_SEARCHES` calls per paid song per session, and `RETRACK_AI_DAILY_LIMIT_USD` per day. A limit hit skips the AI, never crashes, and the song goes to "Check by hand" ("Couldn’t finish the automatic check; here’s how to check by hand."), never into Register or Link by guess. The price never changes because of the AI. Each order's token counts and estimated cost are logged, with counts and dollars only, never catalog data. One `MODEL` for every Claude call. The CLI flags work as before.
- **Web UI: no attestation, no payment, no fixes.** `/pay` checks the attestation checkbox on the server (not just the `required` attribute) and starts no payment without it. The fix page and every download answer 402 until the order is paid.
- **Payments: one charge per order, verified with Stripe.** One Stripe Checkout Session per order (one line, quantity N, at `FIX_PRICE_USD`), never one charge per song. Retrack trusts only Stripe's API: the Checkout Session must be the one stored in `session.order`, its `client_reference_id` must be this Retrack session, `payment_status` must be "paid" and `amount_total` must match. A return URL alone unlocks nothing. Pressing Pay again reuses the open checkout (idempotency key per order); a changed order expires the old checkout; paid songs are never charged again. A paid session stays unlocked for the rest of its 60 minutes.
- **Payments: no card data, no logged keys.** Stripe's hosted page takes the card; Retrack never sees or stores it and never sends Stripe any catalog data (only a random session id, the quantity and the price). Keys come only from `STRIPE_SECRET_KEY` / `STRIPE_PUBLISHABLE_KEY` and are never printed, logged or put in an error message.
- **Payments: test mode by default.** A test key shows "Test payments only. Use card 4242 4242 4242 4242, any future date, any CVC." on the pay step. A live key (`sk_live_`/`rk_live_`) stops Retrack from starting unless `RETRACK_PAYMENTS_LIVE=1`. `--mock` or no keys means "Pay (demo)": no Stripe, nothing charged, works offline. `--mock-mlc` keeps the sample-data banner on every page and uses Stripe test checkout when test keys are set (live keys are still refused without the flag). Recommend a restricted key (`rk_test_…`) with only **Checkout Sessions: Write** (create, retrieve, expire); nothing else is needed.
- **Payments: the signed webhook.** `POST /stripe/webhook` acts only on events whose `Stripe-Signature` verifies with `STRIPE_WEBHOOK_SECRET` (unsigned, badly signed, stale, or no secret set: 400, nothing unlocked). It handles `checkout.session.completed` and `checkout.session.async_payment_succeeded` with exactly `order_is_paid()`'s checks; a repeat or a mismatch unlocks nothing and gets 200 (so Stripe doesn't retry forever). It is the only POST exempt from the Origin check, and only that exact path. For a session already expired and deleted, acknowledge (200), store nothing, and log only the event type and a count: never catalog data, ids or amounts. The return page and `_sync_order()` stay as backups. A hosted version needs its own webhook endpoint and secret from the Stripe Dashboard.
- **Web UI: the fix page warning is true.** The page does not vanish when you leave (a refresh must never lose what someone paid for); it lasts the session's lifetime. So it says "Your fixes stay here for 60 minutes, then your files are deleted for your privacy. Print, download, or screenshot this page to keep it." once, at the top, in the box with the main download, built by `web_pages.keep_text()` from the session lifetime (`SESSION_SECONDS`), never hard-coded, with the time remaining rendered by the server ("About 47 minutes left.") and kept current by JS through `/time_left`. It still asks before leaving (JS only; the page works without it), prints cleanly, and expired sessions say "Your files were deleted for your privacy. Please upload again." `test_warning_text_matches_session_seconds` checks the copy against the constant.
- **Web UI: sample data is labelled.** With `--mock`, every page carries the "Sample data, not real results" banner. Smart names and AI search are off by default, on the pay step ("Extra checks after checkout (optional)", just above the attestation, with the matching "What will leave this computer" text), each with one sentence saying what goes to the AI service and that it runs only after checkout, on the songs you pay for.
- **Web UI: say "AI", not "Claude".** Page copy calls it "an AI service" (users need to know it's an outside AI and what it gets, not which one). Code, comments, the CLI, the README and `docs/` may name Claude. `test_pages_say_ai_not_claude` checks the pages.
- **Web UI: red songs that need AI search** are never a dead end: if AI search was off, the fix page shows the paid red songs under "Check by hand" with one callout holding the AI search checkbox (ticking it is the user's OK to send) and a button that works out only those songs, at no extra charge.
- **AI only suggests.** Matches are labelled "please confirm"; verdicts come from `checker.py`.
- **Every AI feature is opt-in** (`--smart-names`, `--ai-search`, `--smart-import`). The default path never calls Claude, and `--mock` always stays offline.
- **Import: the AI (only with `--smart-import`) only sees the header row and up to `SAMPLE_ROWS` (5) sample rows**, and only answers which column is which. Every row is converted by plain Python; the AI never rewrites data. The user confirms the mapping first (or `--yes`); no terminal and no `--yes` means nothing is converted. Import never drops a row silently: every row that isn't imported is in `import_problems.csv` with its row number. When a writer split is unsure ("Smith, John"), leave it as it is and flag it.

## Rules
- Never commit `.env` or credentials, and never put a real value in `.env.example` (it's committed). `fix_pack/` is git-ignored (it holds catalog data).
- Tests never call the real Stripe or Claude API (fake the client) and never read a real `.env`. `tests/test_ai.py` covers the model, the limits, the cost log and AI-only-after-checkout.
- Don't scrape SoundExchange, BMI or ASCAP sites. Link to them for manual checks instead.
